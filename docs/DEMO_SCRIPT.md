# 3 分钟演示脚本

## 演示前

```bash
make run
```

打开：

```text
http://127.0.0.1:8000/dashboard
http://127.0.0.1:8000/docs
```

建议提前执行一次真实或降级诊断，确保历史记录中有一份可展示报告。

> 它不接真实 MES，也不能代表真实产线经验。重点展示从外部数据、
> SQLite、规则分析、API 到 RAG 和大模型控制的完整工程链路。

指出：

- 数据源名称

操作：

说：

> 设备列表来自当前外部数据文件，不是写死的。切换后，生产批次、
> 异常事件、评分、阈值和趋势会一起更新。

指出：

- 3 个异常事件

- 异常批次 3、正常批次 9

## 0:55–1:25 可解释评分

操作：

- 指向趋势图和“规则扣分”列。

说：

> 趋势按生产批次累计扣分，末点为 45。温度异常扣 15，
> 压力异常扣 10，低良率扣 30，合计 55 分。
> 每个扣分都能反查到批次、参数和阈值。

## 1:25–1:50 数据质量

操作：

- 在 `/docs` 调用 `GET /api/data-quality`。

说：

> 数据文件会先做字段、类型、范围、设备编号、工艺和批次唯一性校验。
> 脏数据整行拒绝且不写业务表。应用仍能启动，通过质量接口查看原因；
> 分析接口会返回 503，不会把旧数据冒充当前结果。

## 1:50–2:20 混合 RAG

操作：

- 调用 `/api/knowledge/search?question=温度传感器异常怎么检查&top_k=3`

说：

> RAG 使用语义段落切分、稳定 chunk_id、文件哈希增量索引，
> 以及向量与 BM25 混合检索。没有可靠匹配时返回 no_match，
> 不会强行给出知识依据。

指出：

- `chunk_id`
- `source`
- `section`
- vector/keyword/hybrid score

## 2:20–2:50 引用与大模型控制

操作：

- 打开一条诊断详情。
- 点击“打开 chunk 原文”。

说：

> 报告保存结构化 JSON、引用和生成方式。模型输出必须通过 Pydantic
> Schema，设备、评分、风险、批次和 chunk_id 都要与事实一致。
> 不合法会重试一次，仍失败就降级为规则报告，所以断网不会 500。

## 2:50–3:00 指标收尾

说：

> 当前有 74 项测试、核心分析覆盖率 86.47%。30 条 RAG 评估的
> recall@3 和负例拒答均达到门禁。项目边界始终是模拟数据。

## 常见追问

### 为什么不用直接读 CSV？

CSV/JSON 是数据入口，SQLite 负责持久查询、索引和分页。文件变化时使用
内容哈希刷新缓存，而不是每次解析整个文件。

### 为什么不用向量数据库？

当前只有 16 个 chunk，引入外部服务没有收益。NPY 精确检索足以演示，
并在 manifest 中记录模型、文件哈希和切分配置。

### 为什么页面不调用 LLM？

仪表盘需要确定性、低延迟和低成本。LLM 报告是单独显式动作，
并带有降级和引用约束。

### 最容易被挑战的地方？

RAG 数据只有 3 个模拟文档，recall=1.0 不代表真实技术文档场景。
下一步需要脱敏真实文档和独立标注问题集。
