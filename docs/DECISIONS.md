# 工程决策记录

| 决策 | 备选方案 | 为什么选它 | 代价 | 边界/不适用场景 |
|---|---|---|---|---|
| 生产模块迁入 `app/`，根目录保留兼容 shim | 一次性删除根模块并重写所有脚本 | 先降低迁移风险，保证现有 URL、CLI 和 import 不中断 | 根目录会暂时保留薄兼容文件 | P1-B 完成调用方迁移后应继续收敛 |
| 使用标准库 JSON 结构化日志 | 引入 structlog/ELK，或继续 print | 当前没有日志平台，标准库足以形成可解析基线 | 暂时只能输出到 stdout，没有集中查询 | 多实例生产环境后续应接入日志平台 |
| 使用 `ContextVar` 传播 request_id | 每个函数显式传 request_id | API、数据同步和 LLM 日志可自动串联 | 异步任务若脱离请求上下文需重新绑定 | 后台任务必须显式设置上下文 |
| 数据文件未变化时先比较元数据，不重新解析全文件 | 每次查询都读取完整 CSV/JSON | 避免小数据测试掩盖大文件性能问题 | 首次使用旧库时可能触发一次全量同步 | 文件哈希本身仍需读取字节流，大规模文件应进一步优化 |
| 启动时数据初始化失败直接终止 | 捕获后继续启动，等首个请求再报错 | 防止“服务看似可用但数据不可用”的假健康状态 | 错误会阻断启动，需要运维查看结构化日志 | 若未来要求降级运行，应显式提供只读/缓存模式 |
| 错误响应同时保留 `detail` 并增加 `error` | 立即只返回新 envelope | 保持现有客户端兼容 | 响应暂时存在字段重复 | P3 版本化 API 时再决定是否移除旧字段 |
| 覆盖率门禁用标准库 `trace` | 安装 coverage.py/pytest-cov | 当前网络不可用，项目仍需要可执行门禁 | 只统计行覆盖，不提供分支覆盖 | 网络可用后可在 P6 替换为 coverage.py |
| 生产/测试/开发依赖分文件 | 所有包放进同一个 requirements | Docker 只装生产依赖，CI 不安装大型向量运行时 | 需要维护三个清单 | 若采用统一镜像构建，可合并为约束文件 |
| 学习稿移到 `scripts/learn/`，运维工具移到 `scripts/tools/` | 保持根目录平铺 | 生产入口与学习代码边界清晰 | 部分命令改为 `python -m scripts...` | 根目录 `main.py` 兼容入口暂时保留 |
| Docker 默认运行完整生产依赖 | 只做 CPU/无 AI 镜像 | `/diagnose` 在镜像内可直接工作 | 镜像包含 torch，体积较大 | 若部署环境不需要 LLM，可另建轻量镜像 |
