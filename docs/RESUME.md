# 简历与面试证据

## 项目名称

半导体设备生产分析与异常识别平台（个人模拟项目）

## 简历 Bullet

### 1. 数据与规则

> 构建 Python/FastAPI 半导体设备分析演示系统，将外部 CSV/JSON 经字段、
> 范围和唯一性校验后同步至 SQLite；实现异常事件、健康评分、批次趋势和
> 逐事件扣分，固定样本覆盖 3 台设备、30 个批次，78 项自动化测试全部通过。

可核验：

- `python scripts/dev.py check`
- 3 台设备、30 批次
- 78 tests

### 2. 接口与性能

> 设计设备、数据质量、分页记录和趋势 API，使用排序白名单、时间范围、
> 4 组 SQLite 索引及增量 schema 迁移；10 万行临时数据下设备分页查询
> P95 约 24.5 ms，时间范围查询 P95 约 19.1 ms。

可核验：

- `python scripts/bench_scale.py`
- `docs/METRICS.md`

### 3. RAG 与 LLM 控制

> 将三套课程式检索逻辑收敛为统一 RAG 管线，覆盖 20 篇设备/工艺文档、
> 102 个带业务元数据的 chunk、持久化索引与向量+BM25 混合检索；建了 50 题
> 段落级金标评估集（含改写、同参数干扰与多证据题），确定性嵌入器下
> recall@3 = 0.86、负例拒答 5/5；生产链路上用 Pydantic Schema、批次/chunk
> 校验和规则降级阻止模型编造事实。

可核验：

- `make rag-eval`
- `python scripts/evaluate_rag.py --embedder semantic`
- `tests/test_llm_control.py`

## 必须写明的边界

- 数据、知识库、阈值和问题集均为模拟内容。
- 未接入真实 MES、SCADA、传感器或工艺配方。
- RAG recall 来自 20 篇模拟文档和 50 条自建问题，不能外推为真实工厂准确率；
  语义模型路径未在本机复测，0.86 是确定性嵌入器下的数字。
- 没有实际线上 DeepSeek 延迟/成本数据。

建议在项目标题或 bullet 后加：

> 项目使用模拟数据，用于验证数据工程、API、RAG 和输出控制流程。

## 10 个面试问题

### 1. 为什么不是直接读 CSV？

CSV/JSON 是可替换的数据入口；SQLite 提供索引、事务、分页和 SQL 聚合。
文件内容哈希变化时才刷新缓存，未变化时跳过重复解析。

### 2. 如何避免脏数据污染旧结果？

校验发生在事务写入之前；脏文件整行拒绝。应用仍可启动，但业务接口返回
503，`/api/data-quality` 只返回当前文件错误，不回退使用旧库。

### 3. 为什么异常事件数可能大于异常批次？

一个批次可同时触发温度、压力和良率规则。事件按命中计数，批次按 batch_id
去重，二者口径不同。

### 4. 健康分是否由大模型计算？

不是。评分、风险和趋势由确定性规则模块计算，LLM 只能解释和给初步建议。
输出 Schema 会校验模型返回的分数和风险是否与事实完全一致。

### 5. 为什么趋势按批次累计？

诊断记录不是每次生产都会产生，直接画历史诊断会让正常设备只有单点。
按外部生产批次累计规则扣分，末点与当前总评分一致。

### 6. 为什么用 SQLite，不上大数据栈？

当前 30 行、10 万行压测都能在毫秒级完成，SQLite 无部署成本。Spark、
Kafka、Kubernetes 与当前规模不匹配，会增加不可解释的复杂度。

### 7. 为什么 RAG 要混合 BM25？

向量模型擅长近义表达，BM25 保留设备号、参数名和规则术语的精确匹配。
当前无词法证据时还提高语义阈值，减少无关问题误召回。

### 8. 如何保证引用不是编造的？

chunk_id 只能来自本次检索结果；finding 中的批次必须属于当前设备；正文
中的 BATCH/LOT/WAFER 编号也会扫描。失败后重试一次，仍失败就规则降级。

### 9. RAG recall@3 = 0.86 是怎么来的，为什么不是 1.0？

早期版本在 3 篇文档、16 个 chunk 上跑出 recall 1.0，那是结构性满分：
候选片段数和 top_k 同阶，等于把库全取回来。后来把知识库扩到 20 篇、
102 个 chunk，并把金标从「文档 + 关键词」收紧到「文档 + 段落」，同时加入
改写、同参数干扰和多证据题，recall@3 落到 0.86，负例拒答仍是 5/5。

面试时这个下降是加分项：说明指标能区分好坏。剩下的缺口集中在改写题
（0.375），原因是确定性嵌入器只能做词面匹配，无法把「热场读数」映射到
「温度」；换语义模型应该能补上，但本机没有 `torch`，我没有实测，不会
把它写成已经达成。

### 10. 系统哪些部分不能用于真实生产？

规则阈值是演示值；没有真实设备安全规程、实时采集、权限和审批；LLM 与
RAG 结果未经工艺工程师确认，不能直接用于维修、参数调整或生产决策。
